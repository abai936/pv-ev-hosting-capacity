## Honest weak spots

1. **Energy balances (rows 24 to 26) are bookkeeping.** Any converged power flow passes them. They catch a missed or double-counted element, not a wrong model.
2. **Hand checks 16 and 18 share `path_r` with the model code.** The prediction uses the same path resistance the model uses to pick the far-end house. They are independent of the OpenDSS solve, not of that helper. The independent checks of the network itself are rows 6 to 8 (published solutions).
3. **The benchmark (rows 6 to 8) tests the feeder and the load model, not PV, EV, inverters or ratings.** It runs the original 1.05 pu / 0.416 kV set-up, not our 1.00 pu / 230 V base case (row 4 checks the ratio and tap logic).
4. **Line ratings are assumed (row 11).** Only the resistance match is checked. The thermal limit binds almost everywhere, so most headline hosting-capacity numbers rest on an unchecked input (see `LIMITATIONS.md`).
5. **The EV session median 6.9 kWh is snippet only (row 22).** The test checks the code against its own inputs.
6. **PV capacity factor (row 20)** compares modelled PVGIS with a table row whose mapping was inferred. A 4.3 % gap is not proof of accuracy.
7. **Inverter curves (rows 12 to 14)** come from free summaries. Var priority (OpenDSS cuts watts first) is an assumption with no source.
8. **No measured data of any kind.** Nothing is compared with a real feeder measurement.
9. **Rows 9, 11, 15, 19, 22 quote a number from a checkpoint report** that was not re-measured in this stage. The test behind each one still passes in the suite.
